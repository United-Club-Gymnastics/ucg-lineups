# Build notes

## Step 1 — scaffold

- **Test config:** a separate `vitest.config.ts` (as in the platform) instead of putting `test` in `vite.config.ts`; vitest bundles its own vite copy and the plugin types clash with vite 8. jsdom for all tests, with RTL `cleanup` in `tests/setup.ts` (vitest globals are off).
- **Tests are not type-checked** by `tsc -b` (same as the platform): the copied `squad-builder.test.ts` has a fixture that fails strict types. They run fine under vitest.
- **No existing platform tests** cover `Field`/`Modal`/`Tabs` directly, so `tests/components/ui.test.tsx` is new (label association, dialog role/Escape/focus trap, tabs, badge).
- **`Field`** loses its `Combo` auto-wiring (Combo not copied); native controls only.
- **Fonts:** `@font-face` URLs are the platform's Supabase `brand` bucket (as copied); `@fontsource` packages are the fallback.
- **Firebase** is initialised but not yet imported by any screen, so it is tree-shaken out of the current build.
- Firebase config files exist but nothing is deployed; `firestore.rules` denies everything until a later step.

## Step 2 — import

- **Vite `base` is now `'./'`** so the built site works at `united-club-gymnastics.github.io/ucg-lineups/` (HashRouter) until the custom domain is set, and at the custom domain afterwards.
- **Bibs are NOT unique per discipline in the real 2026 exports.** 25 discipline+bib keys cover 72 extra rows (bib `1014` is a placeholder shared by dozens of unrelated athletes; the rest are two-club collisions). The spec key `<DISC>_<bib>` is used when a bib is unique; when several athletes share one, every one is kept with id `<DISC>_<bib>~<first-last-slug>` (+`~n` if still clashing), with one `shared-bib` warning per bib. Discipline-export rows are joined by bib, and by first+last name when the bib is shared. **Needs a ruling from Julia** (can ScoreFlippers bibs be fixed, or is the name-suffixed id acceptable?).
- **Parsing:** headers are matched case-insensitively after dropping `_x000d_`/line breaks/extra spaces; rows are keyed by the normalised header. Detection is by headers only. The club email workbook uses the first sheet with "Nationals" in its name, else the first matching sheet.
- **Levels:** the export's `LevelShortName` is used (Dev, Int, Adv, XS, XP, XD, L9, NF…); anything with "Open Scoring" (or short name `Open`) becomes Infinity / `Inf`. Display names drop the `NAIGC ` prefix. T&T athlete level comes from the athletes export; per-event levels (NF/IF/HF) come from the T&T export and are stored only for Included events (`tnt`). For T&T, `apparatus` holds the Included event codes in TR, DM, TU, SY order (same keys as `tnt`), so synchro-only athletes compete with `apparatus: ['SY']`.
- **Independents** ("Independent …" clubs) are flagged `independent: true`, get no `Club` record, no emails and no warnings. Their `clubId` is still the name slug.
- **Warnings** (codes): `shared-bib`, `not-in-export` (athlete missing from a supplied discipline export), `no-export` (discipline export not supplied at all), `unmatched-row`, `email-unmatched`, `no-email` (only when a club email file is supplied), `bad-session`, `missing-bib`, `unknown-type`, `mixed-session`. Athletes missing from the discipline export get `apparatus: []`, `competes: false`.
- **Sessions:** id `s<number>-<gym>`; each real session holds a single discipline. `Session.discipline` is the majority discipline (with a `mixed-session` warning otherwise). Sorted by number then gym order (default Green, Red, Yellow, Orange, Purple).
- **Firestore layer** (`src/lib/data/`): `planImport` is pure and tested; `applyImport` only commits its ops in batches of 450. Athletes are written with `merge: false` (so a scratched T&T event actually disappears); removed athletes get `{ removed: true }` (merge); sessions and clubs merge; existing clubs keep their token and keep stored emails when the import carries none (a re-imported email list does overwrite). `settings/meet` defaults are written only if it does not exist. `clubLinks` is not written yet (step 3). **Nothing has run against a live Firebase project.**
- **UI:** the admin shell holds the tab state in React (no routes yet). Import screen requires "Load stored data" before Apply, so a failed read can never look like "everything is new". ExcelJS is lazy-loaded with the Import screen.
- **Real-export check:** `npx tsx scripts/check-real-exports.mts` (counts only, never names). `tsx` added as a dev dependency. The `scripts/` folder is not type-checked or linted.

## Step 3 — rules + club page

- **Rules (`firestore.rules`):** admin = verified `@unitedclubgymnastics.org` or `admins/{lowercased email}` (as nationals-tools). `settings/meet` public read; `clubLinks/{token}` `get` for anyone, `list` and writes admin-only; `clubOrders/{token}/levels/{levelKey}` readable if the link exists, writable by token holders only when the link exists, `levelKey` is in the link's `levelKeys`, the deadline has not passed and the data is exactly `groups, sections, splitDecided, updatedAt` (`groups` list ≤ 30, `sections` map ≤ 8 keys, `updatedAt == request.time`, so the client must send `serverTimestamp()`). Everything else admin-only. A deadline that is missing, `null` or not a timestamp means "no deadline"; the import now writes `orderDeadline: null` instead of `''`. Rules cannot check the contents of `ids` (no loops), so a token holder can store arbitrary strings in their own club's order docs; the page ignores ids that are not on the roster. **Not deployed; needs Julia's review.**
- **Emulator port is now 8181** (`firebase.json`, `src/lib/firebase.ts`): 8080 is commonly taken by other projects' emulators (it was here). `npm run test:rules` uses it. `@firebase/rules-unit-testing` is pinned to `^5` because v6 needs `firebase@13`. Rules tests run under Node in `vitest.rules.config.ts`; `npm test` excludes `tests/rules`. CI installs Java 21 and runs `test:rules`.
- **Club links:** `buildClubLinks` (pure) writes one `clubLinks/{token}` per club with a token: only `competes` and not `removed`, no independents, no athletes without a known session. Athletes are stored A–Z. Level key `<sessionId>__<levelCode>` (a `/` in a code becomes `-`). T&T sessions appear without levels. `publishClubLinks(db, clubs?)` re-reads athletes/sessions/clubs and batch-writes; it runs after "Apply import" (a failure there is reported but the import itself stays applied). Gym order uses the default, not `settings/meet.gymOrder`. Links of clubs that disappear are not deleted. "Regenerate link" is not built.
- **Order model:** `club-order-model.ts` resolves roster + saved doc to groups/sections with the copied `reconcileGroups`/`sectionsFromGroups`/`splitEvenly` (caps WAG 12, MAG 15). Nothing is written until the club changes something, so the A–Z default is computed on every load; a roster change after saving is reconciled on load (new athletes go first in a group with room) and saved with the next edit.
- **Status** (`club-status.ts`): level `split` = level-wide busiest apparatus > cap and not `splitDecided`; `none` = busiest ≤ 1; `default` = groups equal the A–Z `splitEvenly` and every list is A–Z; else `custom`. Session roll-up as in the spec. There was no prototype to port from here, so this follows the spec text.
- **Autosave** (`autosave.ts`): 600 ms debounce per level, "Saving…" / "Saved · time" / error banner with "Try again" (failed writes stay queued), flush on tab hide and unmount, `beforeunload` prompt while a write is pending. Moving an athlete between groups, auto-split, add/remove group and "Keep this split" set `splitDecided`.
- **Deadline:** read from `settings/meet.orderDeadline` on load and re-checked every minute; after it the page is read-only with a banner (rules enforce it regardless).
- **Cross-group drag (deviation from the platform card, Julia's request):** one `DndContext` holds every group's list for the shown apparatus (one `SortableContext` per group, each group also a droppable; collision prefers the athlete under the pointer, else the group, rectangle overlap for the keyboard). Drop on an athlete = that spot on this apparatus; drop on a group's header/empty area = appended. On the other apparatus the athlete goes first in the new group (`moveAthleteToGroup` + `sectionsFromGroups`, pure `dropAthlete`), and `splitDecided` is set. Caps are not enforced on drop, same as the platform's buttons: an over-cap group is flagged "Split required". The card now shows one apparatus at a time (the page's event tabs). The "→ B" buttons remain as the non-drag way; drop line, Pointer/Touch/Keyboard sensors and announcements (landing position via `dropLandingPosition`) are kept. jsdom can't drag, so component tests feed drag events to the captured `DndContext` handlers.
- **Fixed a Step 1 bug:** an unterminated comment in `src/index.css` hid every `.badge` rule (badges rendered as plain text, including on the admin Import screen).
- **Checked in a browser** against the local Firestore emulator (project id `ucg-lineups`, seeded with invented data): link load, default A–Z, split banner + Keep this split (write accepted by the real rules), status pills, a real pointer drag-reorder and a cross-group drag (right spot on Vault, first on Uneven Bars) persisting across reload, and no horizontal overflow at 375, 768 and 1280 px. Not checked: touch drag on a real device, screen-reader output, the deadline lock in a browser (covered by unit and rules tests), the admin "Apply import" → publish path against a real project.

## Import update — no bibs, League Communications emails (2026-10-18, controller)

- Julia: UCG doesn't use bibs; name + club identify an athlete (birth date as a tiebreaker).
  Athlete id is now `<DISC>_<club slug>_<name slug>` (+ `_<YYYY-MM-DD>` only for same-name
  athletes in one club and discipline). `bib` is gone from `Athlete`; the `shared-bib` and
  `missing-bib` warnings are replaced by `same-name` and `missing-name`.
- Discipline exports are matched by club + name, then by name alone (only when unique or the row
  has no club), with birth date breaking ties. On the 2026 files this cut warnings from 80 to 8 and
  matched 12 more athletes' apparatus.
- The League Communications export (Club, Contact, Role, Season, State) is detected as a club
  email list; only rows whose Role mentions email are used. Unmatched clubs in an email list are now
  one summary warning instead of one per club.
- Any test data imported before this change used bib ids: re-importing marks those as removed and
  adds the new ids (orders saved against old ids would be lost — none exist yet).
- `scripts/check-real-exports.mts` now reads every .xlsx in the folder.
