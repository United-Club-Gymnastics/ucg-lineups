# Build notes

## Step 1 — scaffold

- **Test config:** a separate `vitest.config.ts` (as in the platform) instead of putting `test` in `vite.config.ts`; vitest bundles its own vite copy and the plugin types clash with vite 8. jsdom for all tests, with RTL `cleanup` in `tests/setup.ts` (vitest globals are off).
- **Tests are not type-checked** by `tsc -b` (same as the platform): the copied `squad-builder.test.ts` has a fixture that fails strict types. They run fine under vitest.
- **No existing platform tests** cover `Field`/`Modal`/`Tabs` directly, so `tests/components/ui.test.tsx` is new (label association, dialog role/Escape/focus trap, tabs, badge).
- **`Field`** loses its `Combo` auto-wiring (Combo not copied); native controls only.
- **Fonts:** `@font-face` URLs are the platform's Supabase `brand` bucket (as copied); `@fontsource` packages are the fallback.
- **Firebase** is initialised but not yet imported by any screen, so it is tree-shaken out of the current build.
- Firebase config files exist but nothing is deployed; `firestore.rules` denies everything until a later step.

## Step 2 — import

- **Vite `base` is now `'./'`** so the built site works at `united-club-gymnastics.github.io/ucg-lineups/` (HashRouter) until the custom domain is set, and at the custom domain afterwards.
- **Bibs are NOT unique per discipline in the real 2026 exports.** 25 discipline+bib keys cover 72 extra rows (bib `1014` is a placeholder shared by dozens of unrelated athletes; the rest are two-club collisions). The spec key `<DISC>_<bib>` is used when a bib is unique; when several athletes share one, every one is kept with id `<DISC>_<bib>~<first-last-slug>` (+`~n` if still clashing), with one `shared-bib` warning per bib. Discipline-export rows are joined by bib, and by first+last name when the bib is shared. **Needs a ruling from Julia** (can ScoreFlippers bibs be fixed, or is the name-suffixed id acceptable?).
- **Parsing:** headers are matched case-insensitively after dropping `_x000d_`/line breaks/extra spaces; rows are keyed by the normalised header. Detection is by headers only. The club email workbook uses the first sheet with "Nationals" in its name, else the first matching sheet.
- **Levels:** the export's `LevelShortName` is used (Dev, Int, Adv, XS, XP, XD, L9, NF…); anything with "Open Scoring" (or short name `Open`) becomes Infinity / `Inf`. Display names drop the `NAIGC ` prefix. T&T athlete level comes from the athletes export; per-event levels (NF/IF/HF) come from the T&T export and are stored only for Included events (`tnt`). For T&T, `apparatus` holds the Included event codes in TR, DM, TU, SY order (same keys as `tnt`), so synchro-only athletes compete with `apparatus: ['SY']`.
- **Independents** ("Independent …" clubs) are flagged `independent: true`, get no `Club` record, no emails and no warnings. Their `clubId` is still the name slug.
- **Warnings** (codes): `shared-bib`, `not-in-export` (athlete missing from a supplied discipline export), `no-export` (discipline export not supplied at all), `unmatched-row`, `email-unmatched`, `no-email` (only when a club email file is supplied), `bad-session`, `missing-bib`, `unknown-type`, `mixed-session`. Athletes missing from the discipline export get `apparatus: []`, `competes: false`.
- **Sessions:** id `s<number>-<gym>`; each real session holds a single discipline. `Session.discipline` is the majority discipline (with a `mixed-session` warning otherwise). Sorted by number then gym order (default Green, Red, Yellow, Orange, Purple).
- **Firestore layer** (`src/lib/data/`): `planImport` is pure and tested; `applyImport` only commits its ops in batches of 450. Athletes are written with `merge: false` (so a scratched T&T event actually disappears); removed athletes get `{ removed: true }` (merge); sessions and clubs merge; existing clubs keep their token and keep stored emails when the import carries none (a re-imported email list does overwrite). `settings/meet` defaults are written only if it does not exist. `clubLinks` is not written yet (step 3). **Nothing has run against a live Firebase project.**
- **UI:** the admin shell holds the tab state in React (no routes yet). Import screen requires "Load stored data" before Apply, so a failed read can never look like "everything is new". ExcelJS is lazy-loaded with the Import screen.
- **Real-export check:** `npx tsx scripts/check-real-exports.mts` (counts only, never names). `tsx` added as a dev dependency. The `scripts/` folder is not type-checked or linted.

## Step 3 — rules + club page

- **Rules (`firestore.rules`):** admin = verified `@unitedclubgymnastics.org` or `admins/{lowercased email}` (as nationals-tools). `settings/meet` public read; `clubLinks/{token}` `get` for anyone, `list` and writes admin-only; `clubOrders/{token}/levels/{levelKey}` readable if the link exists, writable by token holders only when the link exists, `levelKey` is in the link's `levelKeys`, the deadline has not passed and the data is exactly `groups, sections, splitDecided, updatedAt` (`groups` list ≤ 30, `sections` map ≤ 8 keys, `updatedAt == request.time`, so the client must send `serverTimestamp()`). Everything else admin-only. A deadline that is missing, `null` or not a timestamp means "no deadline"; the import now writes `orderDeadline: null` instead of `''`. Rules cannot check the contents of `ids` (no loops), so a token holder can store arbitrary strings in their own club's order docs; the page ignores ids that are not on the roster. **Not deployed; needs Julia's review.**
- **Emulator port is now 8181** (`firebase.json`, `src/lib/firebase.ts`): 8080 is commonly taken by other projects' emulators (it was here). `npm run test:rules` uses it. `@firebase/rules-unit-testing` is pinned to `^5` because v6 needs `firebase@13`. Rules tests run under Node in `vitest.rules.config.ts`; `npm test` excludes `tests/rules`. CI installs Java 21 and runs `test:rules`.
- **Club links:** `buildClubLinks` (pure) writes one `clubLinks/{token}` per club with a token: only `competes` and not `removed`, no independents, no athletes without a known session. Athletes are stored A–Z. Level key `<sessionId>__<levelCode>` (a `/` in a code becomes `-`). T&T sessions appear without levels. `publishClubLinks(db, clubs?)` re-reads athletes/sessions/clubs and batch-writes; it runs after "Apply import" (a failure there is reported but the import itself stays applied). Gym order uses the default, not `settings/meet.gymOrder`. Links of clubs that disappear are not deleted. "Regenerate link" is not built.
- **Order model:** `club-order-model.ts` resolves roster + saved doc to groups/sections with the copied `reconcileGroups`/`sectionsFromGroups`/`splitEvenly` (caps WAG 12, MAG 15). Nothing is written until the club changes something, so the A–Z default is computed on every load; a roster change after saving is reconciled on load (new athletes go first in a group with room) and saved with the next edit.
- **Status** (`club-status.ts`): level `split` = level-wide busiest apparatus > cap and not `splitDecided`; `none` = busiest ≤ 1; `default` = groups equal the A–Z `splitEvenly` and every list is A–Z; else `custom`. Session roll-up as in the spec. There was no prototype to port from here, so this follows the spec text.
- **Autosave** (`autosave.ts`): 600 ms debounce per level, "Saving…" / "Saved · time" / error banner with "Try again" (failed writes stay queued), flush on tab hide and unmount, `beforeunload` prompt while a write is pending. Moving an athlete between groups, auto-split, add/remove group and "Keep this split" set `splitDecided`.
- **Deadline:** read from `settings/meet.orderDeadline` on load and re-checked every minute; after it the page is read-only with a banner (rules enforce it regardless).
- **Cross-group drag (deviation from the platform card, Julia's request):** one `DndContext` holds every group's list for the shown apparatus (one `SortableContext` per group, each group also a droppable; collision prefers the athlete under the pointer, else the group, rectangle overlap for the keyboard). Drop on an athlete = that spot on this apparatus; drop on a group's header/empty area = appended. On the other apparatus the athlete goes first in the new group (`moveAthleteToGroup` + `sectionsFromGroups`, pure `dropAthlete`), and `splitDecided` is set. Caps are not enforced on drop, same as the platform's buttons: an over-cap group is flagged "Split required". The card now shows one apparatus at a time (the page's event tabs). The "→ B" buttons remain as the non-drag way; drop line, Pointer/Touch/Keyboard sensors and announcements (landing position via `dropLandingPosition`) are kept. jsdom can't drag, so component tests feed drag events to the captured `DndContext` handlers.
- **Fixed a Step 1 bug:** an unterminated comment in `src/index.css` hid every `.badge` rule (badges rendered as plain text, including on the admin Import screen).
- **Checked in a browser** against the local Firestore emulator (project id `ucg-lineups`, seeded with invented data): link load, default A–Z, split banner + Keep this split (write accepted by the real rules), status pills, a real pointer drag-reorder and a cross-group drag (right spot on Vault, first on Uneven Bars) persisting across reload, and no horizontal overflow at 375, 768 and 1280 px. Not checked: touch drag on a real device, screen-reader output, the deadline lock in a browser (covered by unit and rules tests), the admin "Apply import" → publish path against a real project.

## Step 4 — host artistic squads (MAG/WAG)

- **New pure modules** (the platform's `squad-builder.ts` is untouched; they sit beside it): `rotation.ts` (patterns, squad counts and letters, `rotationFor`, `arrivalOrder`, `routinesPerRotation`), `squad-balance.ts` (cards, plan ops, `autoBalance`, `swapSquads`, flags, capacity guide, specialists), `squad-data.ts` (assemble a session from stored data, club status counts, session sorting, the stored-plan shape). Firestore access is `src/lib/data/squad-store.ts`.
- **Cards** are the platform's whole club-group cards (`deriveClubGroupCards` + `wholeGroups`, empty `squadOf`): one per club group, key `<clubId>::<levelCode>::<groupIndex>::-`; an independent is `indep::<athleteId>::-`. Saved groups are read from every club's `clubOrders/{token}/levels/{sessionId__level}`, reconciled with the copied helpers; a level with nothing saved gets the A–Z default split. Athletes are passed in A–Z order so the default matches the club page. Because the club page orders **per session**, `eventRegs` = the session's own athletes (the platform used event-wide rosters).
- **Stored plan** `squads/{sessionId}`: see the follow-up bullet below (it replaced the first version, which stored card keys only).
- **Auto-balance** is the prototype's algorithm (units placed biggest first; score = over cap, club apart, level mix, busiest apparatus + specialist delay, athletes, squad index) plus: (a) Infinity units first and never mixed with any other level (a club with Infinity and other levels is split per level; Infinity gets only as many squads as its athletes/cap need, so the other levels keep squads); (b) if Infinity cannot be kept apart the card is still placed and flagged. The specialist term is added to the busiest-apparatus term (as in the prototype), not a separate lexicographic tier, so priority 4 and 5 are blended, not strict.
- **Rotations:** a flight-A squad on `byes` has no BYE column; flight B has a leading BYE column (rotation 1). `arrivalOrder` counts a bye as a rotation, so on `byes` flight-B squads arrive one rotation after the matching flight-A squad.
- **Finding in the approved pattern (needs Julia):** with floor shared and no A/B suffix, flight A squad *s* and flight B squad *s+1* are on floor in the same rotation (WAG 8 squads: E and H in rotation 2, C and F in rotation 3, A and D in rotation 4; MAG likewise; Julia confirmed the real 2024 sheet does this, so it stays). The prototype's rotation table hid this (`findIndex` showed one squad). The table now lists every squad on that equipment and sums them. Whether the 2024 meet really ran two squads on one floor (or had a second floor) is a rule question; if not, the pattern needs a different offset for flight B.
- **Deviations from the prototype:** nothing is placed on first open (all groups sit in the tray until Auto-balance; the prototype auto-balanced on load, which here would be an unrequested write). Changing the rotation pattern re-balances as in the prototype, but only asks first when groups are already placed; if nothing is placed it just resizes. Auto-balance and Clear ask for confirmation when something is placed (there is no undo). Cards use level names (Silver XS) rather than codes.
- **Capacity guide:** MAG 80 / 160, WAG 85 for 8 squads, WAG 40 for 4 (the platform figure, still an assumption). Warn only.
- **UI:** `AdminSquads.tsx` (data, session picker, autosave with Saved/Saving/error + Try again, flush on tab hide/unmount) and `SquadBoard.tsx` (dnd-kit: drag by a handle, pointer/touch/keyboard sensors, drop onto a squad or the tray; "Place in squad" and "Swap all groups with" selects are the non-drag way). Squads saved per session; switching sessions keeps the latest edits in memory.
- **Dev affordance:** `VITE_AUTH_EMULATOR_PORT` (default 9099) lets this app's emulators run beside another project's.
- **Checked in a browser** (Vite dev + local Firestore/Auth emulator, project `ucg-lineups`, invented data only; sign-in done by exchanging an unsigned test token with the Auth emulator): both sessions load in gym order, header counts (clubs still A–Z / needing a split), pattern switch to byes (8 squads, two flights, BYE columns), Auto-balance (all placed, Infinity alone in its squad, independent specialist in the squad that reaches their apparatus first), a real pointer drag between squads, the plan written to `squads/s1-green` through the real rules, restored after a reload, and no horizontal overflow at 375, 768 and 1280 px (fixed one: `.sr-only` table headers escaped the scroll box). Not checked: touch drag on a device, keyboard drag, screen-reader output, a large real session.
- **Rebased onto `main` 5bd4ff3** (no bibs; athlete ids are `<DISC>_<club slug>_<name slug>`). Only the squad test fixtures used `bib`; fixed.
- **Saved squads hold athletes, not just groups** (fixes the key-drift weakness). `squads/{sessionId}` = `{ pattern, squads: [{ name, cards: [{ key, athleteIds }] }], trayAthleteIds, schedule, updatedAt }`, no nested arrays. `trayAthleteIds` is an addition to the requested shape: the athletes the host knew about and left unplaced, so an athlete who joined later can be told apart from one deliberately left in the tray. The old `cardKeys` shape is **ignored** (read as nothing saved); there is no live data in it.
- **Restore on load** (`squad-restore.ts`): each saved athlete stays in their squad if they are still competing in the same club and level (the card key says which; independents just need to still compete), even if the club moved them to another group. The cards are then re-derived from the clubs' current groups with the athletes' squads as `squadOf`, so a group split across places shows as one card per place (as in the platform builder). Athletes not in any saved list (new) go to the tray; athletes who left (removed, scratched, changed level or club) drop out. Nothing is written by restoring alone; the first edit saves the reconciled plan. The notice (`N athletes moved since you placed squads`, with club · level · names and the squad) lists three kinds: dropped, new (in the tray) and regrouped (club changed its groups; still in the same squad). It can be dismissed and comes back on the next load until the plan is saved. Auto-balance, Clear and a pattern change reset to whole groups.
- **Re-checked in the browser** (emulator, invented data): placed with Auto-balance, then re-split a club's level into 3 groups, added an athlete to it and removed another from a different club, reloaded: the notice listed the removed athlete (from Squad D), the newcomer (unplaced) and the 8 regrouped athletes; every placed athlete stayed in their squad, the newcomer sat alone in the tray, no horizontal overflow.

## Step 5 — host T&T (squads, per-event order, synchro flights)

- **New pure modules:** `tnt-squads.ts` (primary level, rotation, auto-balance, mixed flags, default order, order reconcile, restore), `synchro-flights.ts` (pair matching, default flights, refresh merge), `tnt-data.ts` (assemble a T&T session; stored-doc shape). Firestore access is `src/lib/data/tnt-store.ts`. UI: `AdminTnt.tsx`, `TntSquadBoard.tsx` and `ReorderLists.tsx` (both built fresh, nothing copied; `ReorderLists` is the dnd-kit list with the drop line, used for the competing order and the flights), `SaveIndicator.tsx` (moved out of `AdminSquads`). `firestore.rules` is unchanged (`squads/{sessionId}` is already admin-only).
- **Stored plan** `squads/{sessionId}` (T&T): `{ kind: 'tnt', squads: [{ name, athleteIds }] ×3, trayAthleteIds, orders: { 'A_TR': [ids], … }, flights: [{ name, pairIds }], pairsReadAt, updatedAt }`, no nested arrays. `trayAthleteIds` is an addition to the requested shape (as in step 4): athletes the host knew about and left unplaced, so a newcomer can be told from someone left out on purpose. `orders` holds only orders that differ from the default (a key is dropped when the order equals the default again), so the default stays live. `flights` is `[]` until the host edits or refreshes. An artistic plan is not read as a T&T one (and vice versa): `kind` / `pattern` decide.
- **First open places nothing** (everyone in the unplaced list) until Auto-balance, as in step 4. Flights are shown as the default from the first read of the Synchro tool but not saved until the host changes something or presses Refresh pairs; viewing writes nothing.
- **Auto-balance** = the prototype's algorithm: units placed biggest first; score per squad = [over 15, club already elsewhere, levels mixed, athletes]. One difference: a club over 15 is split by primary level into pieces of at most 12 that are **near equal** (16 → 8 + 8), where the prototype cut 12 + 4. Primary level = most common level across TR/DM/TU, tie to the higher. Squads are fully filled by the prototype order of priorities, so with more than 45 athletes a squad goes over 15 and is flagged. Synchro-only athletes (entered only in SY) are not placed; they are listed as "Synchro only". An empty squad counts as "no mix", as in the prototype, so a level can end up in two squads when there are spare squads.
- **Mixed-levels flag** is per event, highest first: `Mixed levels: TR HF/IF · DM IF/NF`. Size pill: ok to 12, "above the usual 10–12" at 13–15, "over 15" above that.
- **Order per squad per event:** default HF > IF > NF on that event, then full club name, first name, last name (case-insensitive, then id). Only athletes entered on the event. A newcomer to a custom order is put **before the first saved athlete who sorts after them by the default rule** (so an HF newcomer lands among the HFs, and in an untouched order exactly at the default spot); athletes who left the squad or the event drop out. Moving an athlete between squads drops them from the old squad's orders and puts them at their default spot in the new one. Auto-balance and Clear reset every order. The heavy rule is drawn above a row whose level differs from the row before.
- **Synchro flights:** `fetchSynchroPairs` is read when a session is opened (and again on Refresh pairs). Matching is club + name with spaces and punctuation ignored (the import's `compact`); a name that matches two athletes of one club counts as unmatched. Which session a pair belongs to is not in the Synchro data, so: a pair is shown in a session when at least one athlete matches that session's athletes, or when neither matches any T&T athlete in the import (flagged "Check pair" in every T&T session, so nothing is hidden). A pair with one athlete here and one unmatched or in another T&T session is flagged "Check pair" with the reason, and keeps the Synchro tool's names. Level text is normalised like the import (`High Flyers` → `HF`). **Default flights:** HF > IF > NF (pair level), club, names; split in two, the first flight getting the extra pair. **Refresh merge:** deleted pairs drop out, kept pairs keep flight and order, a new pair is inserted after the last pair of its level in the **last** flight that holds that level (the end of that level's block, which is a plain append when the level is last in the flight), else appended to the last flight; several new pairs go in default order. Pairs saved in a flight but no longer in the Synchro tool stay in the saved data (and out of view) until the next refresh, and a notice says how many are new / deleted since the flights were last refreshed (nothing is silent, and new pairs are never added without the button).
- **Restore** (`restoreTntSquads`): saved athletes who are still entered on TR/DM/TU stay in their squad; athletes who left (removed, scratched, now synchro-only) drop out; athletes not known to the saved plan go to the unplaced list. Both are listed in a dismissible notice, nothing is written until the host edits.
- **Dev seam:** in dev builds only, `window.__ucgSynchroPairs = [...]` replaces the live Synchro read (stripped from production builds: checked `dist` for the string). Offline, the live read cannot be tested.
- **Checked in a browser** (Vite dev + local Firestore/Auth emulator, project `ucg-lineups`, ports 8181 / Auth 9199 via `VITE_AUTH_EMULATOR_PORT`; invented data only, 58 athletes in two T&T sessions; pairs stubbed with the seam): header counts, unplaced start, Auto-balance (3 squads, over-15 and mixed pills for the deliberately oversized data), the plan written through the real rules and restored after a reload, a real pointer drag in the competing order (saved as a custom order), a real pointer drag of a pair from Flight A into Flight B, Refresh pairs (1 added at the end of its level, 1 removed, rest kept), the "changed since" notice after a reload, a "Check pair" for an unknown athlete and a cross-club pair, and no horizontal overflow at 375, 768 and 1280 px. Not checked: touch or keyboard drag on a device, screen-reader output, the live Synchro read, a real import.

## Step 6 — print-ready PDF exports

- **Layout is pure, drawing is separate.** `src/lib/pdf/`: `model.ts` (page models, column specs with `heavy`, shared row-height helpers), `session-input.ts` (stored data -> roster input; the only place that knows about the club orders, squads and T&T plans), the five content modules (`artistic-scorecards-content.ts`, `artistic-rotation-content.ts`, `tnt-scorecards-content.ts`, `tnt-rotation-content.ts`, `synchro-sheet-content.ts`), `collate.ts` (session order, file names, a session's numbered pages), `export-all.ts` (every session + the warnings), `files.ts` (PDF / combined PDF / zip, jsPDF and JSZip loaded on demand), `render.ts` (jsPDF, Helvetica only, letter), `logo-mark.ts` + `svg-path.ts` (the UCG mark as vector data), `pair.ts`, `labels.ts`. The preview (`components/PdfPreview.tsx`) draws the same models in HTML at paper size, so preview == PDF content. Names are `*-content.ts` (the brief) rather than spec §6's `*-pdf-content.ts`.
- **Black and white only**: no fills except a light grey tint (rotation sheet squad band, alternate rows, the T&T rotation table header); a test scans the uncompressed PDF streams for colour operators. Helvetica is a PDF standard font, so no font is embedded. Characters outside Latin-1 are stripped of accents when possible (Ł -> L) and otherwise print as `?`.
- **Logo**: the platform's `mark.svg` path data (provenance row), drawn as black vectors with "UNITED CLUB / GYMNASTICS" beside it in Helvetica Bold. `mark.png` was not copied (60 px, not print quality).
- **Artistic scorecards**: Olympic order, squads by `arrivalOrder` (ties: lower squad first, so the shared floor in the byes pattern shows both squads in the same rotation), 15 rows (athletes then blanks; above 15 everyone still prints), SV and Final Score heavy, Infinity columns when every athlete on that page is Inf (a manually mixed squad gets the standard sheet and the level rule). Names come from the same resolution the club page uses (`resolveLevel` -> `sectionsBy[code][group]`), narrowed to the card's athletes, so a group split across two squads keeps its order in each. **Deviation:** a squad with nobody on an apparatus gets no page for it (the prototype printed an all-blank page). Say if blank spare sheets are wanted.
- **Artistic rotation sheet**: one page per session. Level in the row label is the level *code* (Dev, Int, Adv, XS, Inf), as on the original sheets; an independent's athletes of one level are one row ("Independent Community Athlete – Int", counts added). If a session has more than 60 layout units (a 12-squad MAG session with many small groups) the sheet continues on a second page at a squad boundary instead of shrinking below about 10 pt rows. Squads with nothing placed print their header and "No club groups placed". The subtitle lists only the levels present, in the session's order.
- **T&T scorecards**: 10 rows a page, 5 blanks together on the last page with at least one athlete above, using the prototype's exact algorithm (so 6 athletes print as 5 + (1 athlete + 5 blanks), 15 as 10 + (5 + 5)). Squads with nobody on an event have no page for it. Synchro sheets follow that session's T&T scorecards (portrait, 7 pairs, pairs printed on two lines).
- **T&T rotation sheet**: tables flow across pages (heading repeated "(continued)", never one stranded row). The competition time is not stored anywhere for T&T, so it is a new optional `competitionTime` on `sessions/{id}` (an import merges, so it survives re-import), typed on the Exports screen with its own Save time button. Artistic schedules come from the saved squads document as before.
- **Meet name/date**: `settings/meet.meetName` / `meetDate` already existed in the import defaults; the Exports screen edits them and saves with a merge (deadline and gym order untouched). **No rules change**: `settings/meet` is admin-write/public-read and `sessions` is admin-only; a rules test covers both writes. What you type shows in the preview and downloads immediately, before saving.
- **Collation** (pure, tested): all-sessions scorecards by gym (`settings/meet.gymOrder`, default Green, Red, Yellow, Orange, Purple) then session number; rotation sheets by session number then gym. T&T sessions are in both. Page numbers restart in each session (the same pages are numbered the same in the combined PDF and in the zip). The zip leaves out a session with nothing to print (no squads saved) instead of an empty PDF; the warning list already names it.
- **Synchro flights** use the saved flights, else the default split, read from the Synchro tool when the Exports screen loads. If the tool cannot be read the T&T sessions print without flights and a warning says so.
- **Warnings, never blockers**: no meet name, a session with no saved squads, athletes not placed in a squad (count), an unreadable Synchro tool. Downloads stay enabled.
- **Preview**: every page, scrollable, sticky jump bar (one row per apparatus / event, squad letters; capped at 40% of the viewport height with its own scroll), page `content-visibility: auto`. Each paper scrolls inside its own box; a box that actually overflows gets a tab stop so a keyboard can scroll it. Jump buttons scroll and focus the page (not `#` links, which HashRouter would take).
- **Sample PDFs** come from `npx tsx scripts/make-sample-pdfs.mts <dir>` (invented data in `tests/pdf/fixtures.ts`).
- **Not verified**: printing on paper or a printer's margins, any PDF viewer other than poppler/pdftoppm, a real import's data volume (a full MAG session of ~80 athletes), the live Synchro read, the Exports tab against a live Firebase project, screen-reader output, touch scrolling on a phone.

## Changes 2026-10-18

- **Rotation patterns.** `RotationPattern` is now `'one' | 'parallel'`. `defaultPattern(discipline)`: WAG `parallel` (8 squads), MAG `one` (6), used by the Squads screen and the export input when nothing is saved. The 2024 `byes` pattern is gone from `rotation.ts` (BYE column, shared floor, `startsOnBye`, `RotationRow.byes`), squad balance, the Squads screen (control, flight label, Byes column), the PDF content/render/preview, tests and spec. `readPattern()` reads a stored `byes` as `parallel` (same squad count and start apparatus, so saved cards keep their squads); `parseSquadDoc` then sets `removedByes: true` (never written), and the Squads screen shows "This session used the 2024 bye pattern, which has been removed; it now uses two flights on A/B equipment." until the host's next change saves the plan as `parallel`. Existing page tests written for 4 WAG squads now click "One flight" first.
- **Synchro pair sessions; storage choice.** One admin doc, `synchroSessions/main` = `{ assignments: { <pairId>: <sessionId> }, updatedAt }` (`src/lib/data/synchro-store.ts`), covered by the catch-all admin rule, so **`firestore.rules` is unchanged**. Chosen over per-session unassigned lists because a choice must survive a refresh of any session's flights and be read by Exports without loading every session. Per-session flights in `squads/{sessionId}.flights` still hold order. `placePairs()` (pure) gives each pair `sessionId`: the stored choice (ignored if that session no longer exists), else the session both athletes share, else null = "Needs a session". Refresh pairs never writes assignments. Moving a pair to another session removes it from this session's saved flights at once; moving it into this session merges it into the saved flights; for a session the host has not opened since, the pair appears via the existing "new pair, press Refresh pairs" notice. Exports merge saved flights with the session's current pairs (so moved pairs print) and warn when pairs were not yet in the saved flights.
- **Matching.** Club + name first; then name alone when exactly one T&T athlete in any session has it (clubs were renamed after the Synchro tool read February's roster); a same-name tie uses the partner's club, then the partner's session, else stays unmatched. Name-only matches are not flagged and show the import's current name and club; Synchro-tool names remain only for unmatched athletes. Unmatched pairs appear once, under Needs a session, not in every session (this replaces the old "shown flagged in every session"). "Check pair" also covers an athlete on the roster but not entered in synchro. `matchPairs`/`TntSessionData.elsewhere` were replaced by `placePairs`/`buildTntRoster`.
- **Import summary** (`AdminImport.tsx`): columns renamed "Entries" and "Competing on at least one event", with the line "Entries scratched from every event aren't placed in groups, squads or sheets." The table caption still reads "Athletes by discipline".

## Changes 2026-10-18 (batch b)

- **Pair-matching wording.** `buildTntRoster` now returns every non-removed T&T athlete with a `competes` flag (a scratched athlete has no events). `placePairs` matches only competing athletes, so a scratched athlete never places a pair; the flag only picks the message: "<name> is scratched from every event", "<name> isn't in this import" (truly absent), or "is on the roster but not entered in synchro".
- **Per-pair assignment writes.** `saveSynchroAssignment(db, pairId, sessionId | null)` is a merge `setDoc` of `{ assignments: { [pairId]: sessionId | deleteField() } }`. The pair id is a map key, never parsed as a field path, so dots or slashes are safe, and the doc is created if missing. (`updateDoc` with `FieldPath` would also work but fails on a missing doc.) Two admins choosing for different pairs no longer overwrite each other. Rules test added; `firestore.rules` is unchanged.
- **Session schedule.** `src/lib/schedule.ts` (pure): `resolveSchedule(number, rows, override, fallbackDate)` (override wins per field, then the number's row, date then the meet date), date formatting, `whenText` (weekday + competition, no double weekday), and the migration planner. UI: a "Session schedule" card on the Exports screen (table by session number, collapsible per-session overrides, Save buttons that write only changed rows/sessions with merge writes) replaces the per-T&T "Competition time" field; the Squads screen's three time inputs are replaced by a link to it. Exports resolve through `applySchedules` (also used for not-yet-saved typing). The date input stores ISO `yyyy-mm-dd`; the header prints it as "October 22, 2026"; free text still prints as typed.
- **Migration** (`planMigration`, `runScheduleMigration`): only on the button, never on load. Old `squads/{id}.schedule` and `sessions/{id}.competitionTime` values that differ from their number's row become that session's override (an existing override is never replaced); equal ones are dropped; then the old fields are cleared (`schedule` set to empty strings, `competitionTime` deleted). Overrides are written first, so a failure part-way leaves the old times in place. Until it is run, those old times are no longer printed. `StoredSquadDoc.schedule` still exists and is carried along unedited.
- **Browser check** (Vite dev + Firestore/Auth emulator, invented data, synchro pairs injected through the dev-only `window.__ucgSynchroPairs`): "Needs a session" list and the schedule table at 375, 768 and 1280 px: no horizontal overflow; computed text and placeholder contrast all above 4.5:1 (placeholder 5.43:1); the table stacks into labelled two-column cells below 760 px. Saving a row, and the migration button, wrote to the emulator through the real rules. Note: the first load of the T&T/Exports screens in dev read the LIVE Synchro tool (public, read-only) before the hook was set; nothing from it was stored. Not checked: a real device, screen-reader output, the date picker on Safari.
